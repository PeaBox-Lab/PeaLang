# Type help

Use optional annotations, generics such as `function first<T>(items: List<T>) -> T?`, protocol bounds such as `function show<T: Printable>(value: T)`, marker traits such as `trait Serializable`, and `Result<T,E>`, `Option<T>`, `Future<T>`, `Iterable<T>`, `Iterator<T>`. Static analysis scopes type parameters, infers type arguments at call sites, checks bounds, compares nested generic arguments, verifies structural protocol signatures with `P201`–`P205`, reports `I201` for known non-iterable `for` targets, and models `async function` declarations as `Future<T>` with `A201` diagnostics for awaiting known non-futures. Conformance is checked only for protocols or traits used in generic bounds. Runtime annotations, protocols, traits, and async annotations remain erased. Project analysis also builds a module graph and reports `M201` for unresolved imports and `M203` for import cycles. Safe metaprogramming uses validated `SafeMacro` definitions with named metavariables and hygiene markers, reporting `MG101`-`MG203` issues before expansion. Resource scopes use `using` bindings with guaranteed cleanup and report `R201`/`R202` for duplicate or reassigned bindings. The v2 conformance suite checks interpreter/VM parity, macro expansion, static diagnostics, and module graphs with a stable PASS/FAIL gate. The frozen 3.0 core combines conformance, public API removals, specification verification, and version agreement into the `pea freeze` gate. The bytecode optimizer applies conservative peephole passes to `.peac` artifacts and checks VM output parity with `pea optimize --verify`. The fast interpreter uses direct-handler dispatch for supported bytecode, falls back to the standard VM otherwise, and verifies parity with `pea fast --verify`. The bytecode JIT profiles instruction counts, compiles hot loop back-edges with guarded integer specialization, deoptimizes on guard failure, and verifies parity with `pea jit --verify`. The native backend lowers supported bytecode to deterministic native IR and self-contained C source, falls back to the standard VM for unsupported modules, and verifies parity with `pea native --verify`. The WASM backend lowers supported bytecode to typed WASM IR in a custom-section module with a reviewable `.wat` artifact, falls back to the standard VM for unsupported modules, and verifies parity with `pea wasm-backend --verify`. The parallel runtime runs isolated bytecode tasks in a bounded worker pool with ordered output and VM fallback, verified by `pea parallel --verify`. The runtime profiler records deterministic opcode, function, and line counts with `pea profiler --verify`, while `pea perf-gate` applies versioned 4.0 budgets together with parity, conformance, and frozen-core evidence. LSP v2 adds a deterministic editor layer with versioned capabilities, incremental document synchronization, and inspectable diagnostics, symbols, hover, completion, references, rename, formatting, folding, inlay hints, and semantic tokens; `pea lsp --check` and `lsp_v2_gate()` provide CI-ready evidence. DAP v2 adds a reproducible VM-backed debug session with versioned capabilities, conditional breakpoints, deterministic stop events and snapshot fingerprints, and reviewable stack, scope, variable, evaluation, exception, and disconnect responses; `pea dap-v2 --check` and `dap_v2_gate()` provide CI-ready debugger evidence.
