# Type help

Use optional annotations, generics such as `function first<T>(items: List<T>) -> T?`, protocol bounds such as `function show<T: Printable>(value: T)`, marker traits such as `trait Serializable`, and `Result<T,E>`, `Option<T>`, `Future<T>`, `Iterable<T>`, `Iterator<T>`. Static analysis scopes type parameters, infers type arguments at call sites, checks bounds, compares nested generic arguments, verifies structural protocol signatures with `P201`–`P205`, reports `I201` for known non-iterable `for` targets, and models `async function` declarations as `Future<T>` with `A201` diagnostics for awaiting known non-futures. Conformance is checked only for protocols or traits used in generic bounds. Runtime annotations, protocols, traits, and async annotations remain erased. Project analysis also builds a module graph and reports `M201` for unresolved imports and `M203` for import cycles. Safe metaprogramming uses validated `SafeMacro` definitions with named metavariables and hygiene markers, reporting `MG101`-`MG203` issues before expansion. Resource scopes use `using` bindings with guaranteed cleanup and report `R201`/`R202` for duplicate or reassigned bindings. The v2 conformance suite checks interpreter/VM parity, macro expansion, static diagnostics, and module graphs with a stable PASS/FAIL gate. The frozen 3.0 core combines conformance, public API removals, specification verification, and version agreement into the `pea freeze` gate. The bytecode optimizer applies conservative peephole passes to `.peac` artifacts and checks VM output parity with `pea optimize --verify`.
