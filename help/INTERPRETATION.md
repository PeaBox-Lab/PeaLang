# Model interpretation help

Use `stats` (or `std.stats`) to explain fitted tree, forest and boosting models; everything is dependency-free and returns ordinary records. Permutation importance: `permutation_importance(model, features, target, task, n_repeats, seed, scoring, names)` scores the model once as `baseline`, shuffles each column `n_repeats` times, and reports the metric drop as a sorted `{feature, mean, std, values}` table. Importance is `baseline - shuffled` for higher-is-better metrics (`r2`, `accuracy`, `balanced_accuracy`, `f1`, `roc_auc`) and `shuffled - baseline` for lower-is-better metrics (`mse`, `rmse`, `mae`, `log_loss`). Partial dependence: `partial_dependence(model, features, columns, grid_size, task, names)` sweeps each selected column over an evenly spaced grid between its observed min and max, averages predictions at each point, and returns `curves`. Regression curves carry `values` and `average`; classification curves also carry `classes` and per-class `probabilities`, with `average` equal to the last (positive for binary) class. `columns` accepts indices, names when `names` is supplied, or `null` for all features. Record wrapper: `analysis.interpret_report(data, target, features, estimator, task, params, n_repeats, grid_size, seed, scoring, columns)` fits `"tree"`, `"forest"` or `"boosting"` from records and adds `features`, `importance`, `permutation_importance`, `partial_dependence`, `baseline`, `scoring` and `n_used`. `task = "auto"` infers classification for boolean, non-numeric and low-cardinality integer targets. `tree` models have no probabilities, so probability-based metrics and curves need `forest` or `boosting`. See `docs/MODEL_INTERPRETATION.md`.
