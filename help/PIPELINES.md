# Feature pipeline help

Use `stats` (or `std.stats`) to build preprocessing pipelines; everything is dependency-free and returns ordinary records. Steps are records applied in order: `{"op": "impute", "method": "auto"|"mean"|"median"|"mode"|"constant"|"zero"}`, `{"op": "date", "parts": [...], "required": true|false}`, `{"op": "target", "columns": [...], "smoothing": 10.0, "min_count": 1, "required": true|false}`, `{"op": "encode", "method": "onehot"|"ordinal"|"label"}` and `{"op": "scale", "method": "standard"|"minmax"}`; aliases are `fillna` for impute, `calendar` for date, `target_encode` for target and `standardize` for scale. `constant` needs a `value`. `auto` imputes means for numeric columns and modes for categorical ones. A date step detects columns whose observed values all parse as dates and replaces each with `name=part` calendar columns; `parts` defaults to year, month, day, weekday, quarter and is_weekend, and `required` defaults to true (`false` makes a missing date column a no-op). Missing dates must be imputed before the date step. A target step replaces categories with smoothed target means, using `(count * mean + smoothing * prior) / (count + smoothing)`; `columns` limits it to named columns (otherwise all non-numeric columns are encoded), levels below `min_count` and unseen categories use the prior, and `required` defaults to true (`false` makes an all-numeric feature set a no-op). A target is passed as the fourth argument to `fit_pipeline`; numeric targets are used as-is, two-class labels map to `0`/`1` in sorted order, and more than two non-numeric classes raise. Target encoding uses the training target, so fit it on training data and apply it to held-out rows. Encoding treats a column as categorical when any observed value is not a number; one-hot produces `name=level` columns (missing becomes `name=null`, unseen levels become all zeros), ordinal produces level indices (unseen levels become `-1`). Scaling requires numeric, non-missing values, so impute, date, target and encode first. `fit_pipeline(steps, features, names, target)` returns `{steps, features, names, input_names, n_features, n}` with learned fill values, levels, date parts, target means, centers and scales; `transform_pipeline(transformer, features)` reapplies them and returns `{features, names}`. `names` defaults to `x1`, `x2`, ... and the transform input width must match. Model wrappers: `analysis.model_pipeline(data, target, features, steps, estimator, task, params)` builds the raw matrix from records, fits the pipeline and estimator, and stores `preprocessor`, `features`, `output_features`, `importance`, `n_used` and training diagnostics; `steps = null` uses impute, date expansion, one-hot and standard scaling. A target step receives the training outcomes automatically. `analysis.predict_pipeline(model, data)` accepts records or a raw matrix and returns the estimator prediction record. Missing targets are dropped; missing features need an impute step. See `docs/FEATURE_PIPELINES.md` and `docs/DATE_FEATURES.md`.
