# Feature pipeline help

Use `stats` (or `std.stats`) to build preprocessing pipelines; everything is dependency-free and returns ordinary records. Steps are records applied in order: `{"op": "impute", "method": "auto"|"mean"|"median"|"mode"|"constant"|"zero"}`, `{"op": "encode", "method": "onehot"|"ordinal"|"label"}` and `{"op": "scale", "method": "standard"|"minmax"}`; aliases are `fillna` for impute and `standardize` for scale. `constant` needs a `value`. `auto` imputes means for numeric columns and modes for categorical ones. Encoding treats a column as categorical when any observed value is not a number; one-hot produces `name=level` columns (missing becomes `name=null`, unseen levels become all zeros), ordinal produces level indices (unseen levels become `-1`). Scaling requires numeric, non-missing values, so impute and encode first. `fit_pipeline(steps, features, names)` returns `{steps, features, names, input_names, n_features, n}` with learned fill values, levels, centers and scales; `transform_pipeline(transformer, features)` reapplies them and returns `{features, names}`. `names` defaults to `x1`, `x2`, ... and the transform input width must match. Model wrappers: `analysis.model_pipeline(data, target, features, steps, estimator, task, params)` builds the raw matrix from records, fits the pipeline and estimator, and stores `preprocessor`, `features`, `output_features`, `importance`, `n_used` and training diagnostics; `steps = null` uses impute, one-hot and standard scaling. `analysis.predict_pipeline(model, data)` accepts records or a raw matrix and returns the estimator prediction record. Missing targets are dropped; missing features need an impute step. See `docs/FEATURE_PIPELINES.md`.
