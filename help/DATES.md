# Date feature help

Use `stats` (or `std.stats`) to turn date strings into numeric calendar features without dependencies. `stats.is_date(value)` returns a boolean. `stats.date_parts(value, parts)` returns a record for one date. `stats.calendar_features(values, parts, prefix)` expands a sequence into `{features, names, parts, n}`. `analysis.date_features(data, column, parts, prefix, drop_original)` adds `<column>_<part>` columns to records and keeps the other columns. Parsing accepts `YYYY-MM-DD`, `YYYY/MM/DD`, `YYYY.MM.DD`, `YYYYMMDD`, optional `T`/space time suffixes and Python date/datetime values; time and timezone are ignored. Parts are `year`, `month`, `day`, `weekday` (Monday `0` to Sunday `6`), `quarter`, `day_of_year`, `week` (ISO), `is_weekend`, `is_month_start`, `is_month_end`, `epoch_day` (days since 1970-01-01), `month_sin`, `month_cos`, `weekday_sin` and `weekday_cos`; defaults are year, month, day, weekday, quarter and is_weekend. The pipeline step `{"op": "date", "parts": [...], "required": true}` detects date-like columns, replaces each with `column=part` columns and passes other columns through; `required` defaults to true and `false` makes the step a no-op when no date column exists. Missing dates must be imputed first, so order steps impute, date, encode, scale. `analysis.model_pipeline` uses impute, date, encode and scale when `steps` is null, so dates are expanded automatically. Fitted date steps persist through `stats.save_model`. Invalid dates raise with the row index. See `docs/DATE_FEATURES.md`.
