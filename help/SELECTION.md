# Model selection help

Use `stats` (or `std.stats`) for tuning; everything is dependency-free and returns ordinary records. Estimators are named by string: `"tree"`, `"forest"` or `"boosting"` (aliases `"decision_tree"`, `"random_forest"`, `"gradient_boosting"`, `"gbm"`). Cross-validate: `cross_validate(estimator, features, target, task, params, folds, seed, scoring, shuffle)` returns per-fold `scores` plus `mean`, `std` and `higher_is_better`. Grid search: `grid_search(estimator, features, target, task, param_grid, folds, seed, scoring, shuffle)`; `param_grid` maps parameter names to non-empty lists. Random search: `random_search(estimator, features, target, task, param_grid, n_iter, folds, seed, scoring, shuffle)`, seeded so the same seed samples the same candidates. Both searches return `best_params`, `best_score`, `best_std`, a `best_model` refit on all rows, and a ranked `results` table. `scoring = "auto"` picks `r2` for regression and `accuracy` for classification; regression also accepts `mse`, `rmse`, `mae`, `explained_variance` and classification accepts `balanced_accuracy`, `f1`, `roc_auc`, `log_loss`. `roc_auc` and `log_loss` need binary probabilities. Record wrappers: `analysis.tune_model(data, target, features, estimator, task, param_grid, folds, seed, scoring)` and `analysis.random_tune(data, target, features, estimator, task, param_grid, n_iter, folds, seed, scoring)`; both add `features`, `n_used` and a `best_model.importance` table. See `docs/MODEL_SELECTION.md`.
